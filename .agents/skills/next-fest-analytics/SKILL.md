# 体験版の計測

Unity Dashboard の production 環境で、依頼された期間の遊ばれ方を調べる。分析の依頼は閲覧と報告までを含む。issue コメント、保存レポート、イベント定義の変更は、依頼または既存の明示的な許可がある場合に行う。

## 必要な情報を読む

- イベントの意味・areaName・bossName は [イベント対応表](references/events.md)。
- Dashboard の場所、到達ファネル、死亡の集計、受信トラブルは [Dashboard 操作](references/dashboard.md)。
- 計測記録の作成・投稿を依頼された場合は [記録例](references/reporting.md)。

送信元は `Assets/Scripts/Core/VLCNPAnalytics.cs`。Editor / Development Build は送信をスキップする。送信が疑わしい場合はコード・Player.log・Event Browser を照合する。

## 数字の解釈

- 集計期間、タイムゾーン、取得時刻、環境、イベント回数かユニークユーザー数かを明記する。
- 未取得・反映待ち・取得不能を 0 と書かない。0 は指定条件で集計を確認できた場合だけ使う。分母が 0 / 不明なら率は算出不能。
- Event Browser は受信確認用の限定された表示。表示件数を期間全体のイベント数や到達ユーザー数にしない。
- ファネルは順序・期間・条件に合う集団の値。あるエリアの全到達者数と同じとは限らない。
- シーン死亡回数をエリア到達者数で割った値は「エリア到達者あたりの当該シーン死亡回数」であり、シーン到達者の死亡率ではない。分子と分母の対象集団・期間が合わなければ割らず別々に示す。
- 自分のテストプレイや再訪が混ざる可能性と、集計の遅延を考慮する。観測値から言えることと原因の推測を区別する。

開催日や Dashboard の表示・反映時間は実行時に確認する。過去の観測を恒久的なサービス仕様や確定値の保証にしない。
